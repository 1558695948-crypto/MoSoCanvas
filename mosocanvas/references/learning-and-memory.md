# Learning, task records and persistent memory

MoSoCanvas does not train model weights or automatically rewrite its own aesthetic rules. Separate
three mechanisms when explaining what the system remembers.

## Within the current task

The Visual Spec, approved checkpoint, Feedback Delta, attempt reviews and run state preserve
decisions across rounds. Read them before a new attempt. Carry accepted unexpected features into
the next preservation contract. Do not recreate rejected alternatives or reopen accepted tradeoffs
without new evidence. This is executable workflow state, not a learned model preference.

## Evidence from completed work

Record a useful observation beside its run artifacts as a **learning candidate**, including:

- the actual situation and narrow task scope;
- what was observed, separated from interpretation;
- parent/candidate, review and user-decision references with hashes when available;
- whether a change improved the named criterion;
- alternative explanations and cases where the observation might not apply;
- proposed follow-up test, user preference status, and `status: candidate`.

Do not infer user taste from a reviewer majority. One image with three reviewers is one case, not
three independent tasks. Do not promote a candidate merely because it has no dissent. Improvement
claims require actual before/after evidence, and broader claims need the existing matched-task
evaluation protocol. An unexecuted suggestion cannot become a successful-repair lesson.

Candidates are ordinary project evidence records. They do not automatically load into every new
task, modify the direction catalog, or change the Skill. When revising the method, retrieve relevant
records, check scope and counterexamples, propose a narrow change, and validate it against fresh
tasks before describing it as a supported improvement.

## Across tasks

Host-provided memory may retain explicitly recorded brand conventions, preferences and prior
decisions. Its availability and update permissions belong to the host. Follow those instructions;
this Skill grants no permission to write a persistent memory store. Keep technical observations,
confirmed user preferences and universal rules separate. Recheck stale facts and honor current
user choices over historical assumptions.

Without an available, authorized persistence mechanism, report the project record location and
state that cross-task automatic recall is not implemented. Never claim that the model has learned
the user's taste merely because a review report was saved.
